# 广告实验组间干扰分析系统（合成数据演示）

按**商户**随机分臂的广告实验，用户却会**跨商户访问**：同一用户既看到处理组
商户、又看到对照组商户的广告（组间干扰 / 污染）。曝光、转化、退款**分批
到达**，期间还会发生**身份归并**与**曝光归因修订**。本系统在这种数据上提供：

- **按原分配（as-assigned）与实际接触（as-treated）同时展示**的描述统计；
- **三种估计单位**（用户 / 商户 / 曝光聚类）的效应估计与**可复现的不确定性
  比较**，并说明样本量与独立性的取舍；
- **污染路径**可视化、**组贡献下钻**、**报告并排比较**；
- **输入版本化**：历史报告保持自己的输入版本，身份归并 / 曝光修订只产生
  新快照，后台重算绝不把新旧分组混进同一份报告；
- 受污染用户**保留并标记**——删除他们再宣称随机实验结论是不成立的
  （分析页只把"剔除后"数值作为明确标注的敏感性参考）。

> ⚠️ 全部数据为**合成生成**（处理臂转化概率相对 +25% 的构造），仅用于演示
> 分析方法，**不宣称任何真实投放效果**。

## 快速开始

纯 Python 3 标准库，无第三方依赖（开发环境 3.11）。

```bash
# 一键演示：合成数据 → 两阶段入库 → 两个输入版本 → 各出一份报告
python3 -m app.demo

# 启动网页（另开一个终端）
python3 -m app.server --db data/app.db --port 8000
# 打开 http://127.0.0.1:8000

# 可选：后台工作进程（网页上创建的报告由它拾取计算）
python3 -m app.worker --db data/app.db

# 测试
python3 -m unittest tests.test_core -v
```

也可以在网页"总览"页点 **一键演示** 按钮完成同样的流程。

## 模块

```
app/
  db.py        SQLite 模式：批次 / 事件 / 归并 / 修订 / 快照 / 报告（全部追加式）
  ingest.py    批次接入：sha256 文件幂等、event_uid 幂等、行级校验与 DQ 计数
  analysis.py  快照输入装载 → 分析帧（用户/商户/聚类）→ 四种口径 + bootstrap
  worker.py    后台工作进程：只读自己快照的输入，计算并落库，旧报告不改写
  server.py    网页：总览 / 分析页 / 污染路径 / 组贡献 / 报告比较 / 方法说明
  synth.py     合成数据生成器（确定性种子）
  demo.py      一键演示流水线
tests/test_core.py  接入幂等、快照隔离、归并/修订生效、可复现性
```

## 数据流与版本语义

```
CSV 批次 ──ingest──▶ batches(不可变) ──┐
                                       ├─ snapshot = 输入版本（批次 ≤ K）
归并/修订/新批次 ──ingest──▶ 新批次 ────┤        │
                                       ▼        ▼
                          report = (snapshot, seed, n_boot, 代码版本)
                                       │
                                       ▼
                          sections（结果 JSON，写入后只读）
```

- **批次（batch）**：一次入库的文件，带 sha256；同一文件重复入库被拒绝，
  事件按 `event_uid` 幂等。批次只增不改。
- **快照（snapshot）**：实验的输入版本，定义为 `batch_id ≤ K` 的全部输入。
  身份归并、曝光修订、迟到事件到达后，**冻结新快照**而不是改旧数据。
- **报告（report）**：对某个快照用固定参数（seed、n_boot、代码版本）的一次
  完整计算。worker 计算时**只读** `batch_id ≤ K` 的行，新旧分组不会混入；
  历史报告永不改写，重算只会产生新报告。网页可并排比较两份报告，若输入
  版本不同会明确提示"差异可能来自输入而非方法"。

## 批次文件格式（CSV）

| 文件 | 列 |
|---|---|
| 事件 | `event_uid,event_type(exposure/conversion/refund),user_id,merchant_id,ts,amount,order_id` |
| 分组 | `merchant_id,arm(control/treatment)` |
| 身份归并 | `merge_id,primary_user,secondary_user` |
| 曝光修订 | `revision_id,event_uid,new_merchant_id,reason` |

入库时按表头自动识别类型。数据质量规则：

- **重复转化**：同一 `order_id` 只计首条，重复条数与金额计入 DQ（原始日志保留）；
- **无法匹配的退款**：不计入净收入，仅在 DQ 留痕；
- **身份归并**：并查集归并到最小 id，快照内生效；
- **曝光修订**：改写的只是该快照内的事件视图，旧快照报告不受影响。

## 估计单位与取舍

| 口径 | 单位 | 独立性 | 样本量 | 解读 |
|---|---|---|---|---|
| 用户级 ITT | 用户（首次曝光归属） | 弱：同商户用户相关、跨组用户接触两臂 | 最大 | "按分配意图"的效果；跨组接触使其向零衰减；**受污染用户保留并标记** |
| 商户级 | 商户（随机化单位） | 强 | 小（数十） | 无群内相关偏倚，但检验效能低、CI 宽 |
| 聚类级 | 曝光图连通分量 | 最强：分量间无曝光边 | 最小，且仅**纯组聚类**参与估计 | 只外推到无干扰子总体；混合聚类体量即干扰规模 |
| 实际接触 | 用户（按实际曝光） | 非随机化 | 大 | 描述性，自选偏差，不作因果结论 |

分析页同时给出四种口径和并排的 95% CI 图示：没有唯一"正确"口径，
页面展示的是**取舍本身**（用户级 CI 最窄但独立性最弱，聚类级反之）。

**关于删除受污染用户**：删除依赖于试验后行为，破坏随机化可比性。本系统
在 ITT 口径中保留受污染用户并单独标记其规模与贡献；"剔除后"的数值仅以
红色横幅标注为**非随机化的敏感性参考**，不得据此宣称实验结论。

## 可复现的不确定性

- 双臂分别重抽样的 percentile bootstrap（默认 n_boot=1000）；
- 随机数由 `seed:快照:口径:指标` 派生（sha512 播种），所有单位列表先按
  id 排序——**同一快照 + 同一参数重算，结果逐位一致**（有测试保证）；
- Welch t 的 p 值为正态近似，仅供参考，以 bootstrap CI 为准。

## 合成数据的世界设定

30 个商户按商户级分层随机分臂（15/15）：20 个"孤立商户"（七成用户只逛
一家 → 纯组聚类）+ 2 个"开放商圈"（三成用户跨店逛 1~3 家 → 跨组污染与
混合聚类）。另有 8% 退款、3% 重复转化、0.5% 无法匹配退款、60 例身份归并、
12 条曝光修订，分 7 个批次到达。生成器种子固定（默认 20261116），
数据完全确定。
